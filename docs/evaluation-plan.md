# AutoResearch Eval：最小研究计划（草案）

## 核心假设

一个能够可靠识别执行环境状态、保存科研证据并恢复实验的 Agent 系统，在相同预算下可能显著提升任务完成率；但必须控制模型、任务难度、工具权限和环境条件，才能判断提升来自 Agent 还是基础设施。

## 评测单位

以 **Campaign → Experiment → Attempt → Event** 为层级，明确：
- 科研目标、配置及预算；
- 实验与每次尝试的唯一身份；
- Agent 决策与可见上下文；
- 工具调用及资源状态；
- 结果、失败类别、证据及最终状态。

## 第一阶段：Trace Collection

优先从可公开的合成或获授权记录开始，构建最小事件 schema。不要直接公开生产 Codex JSONL、平台认证或私有实验输入。

## 第二阶段：Fault Attribution

建立标签：Scientific / Engineering / Environment / Mixed / Unknown。每个标签必须附证据，双人标注并报告分歧及一致性。

## 第三阶段：Controlled Comparison

固定任务、模型、时间与 GPU-hours，比较：
- 普通一次性 Agent 执行；
- 具有持久状态但无自动恢复的执行；
- 具备安全恢复和任务去重的执行。

故障注入需包括中断、配额不足、重复提交、工具权限拒绝。必须区分安全拒绝与能力失败。

## 指标

任务成功率、可验证有效进展、总完成时间、P95 任务延迟、GPU-hours/完成任务、重复计算开销、人工干预次数、归因准确率与证据完整率。

## 可能的混杂因素

研究难度、模型更新、外部 API 不稳定、计算资源争用、平台权限、硬件规格、初始 checkpoint 和评测泄漏。

## 当前缺口

没有已发布轨迹数据集；没有正式专家标注或受控对照实验。该计划用于指导下一轮采样与实验，不应包装成现有 Benchmark。
