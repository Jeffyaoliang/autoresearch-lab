# 研究简介：超越最终结果的自主科研 Agent 评测

**主题：** 面向真实计算环境的长时程 AutoResearch Agent 过程级评测（Process-level Evaluation）

## 背景

自主科研 Agent 的能力不仅取决于生成研究设想，还取决于能否在真实的代码、数据、GPU 与实验环境中持续执行：运行实验、处理故障、保存状态、比较证据并决定后续研究步骤。

只看最终指标容易混淆：
- **科学错误**：假设或实验设计本身没有产生有效增益；
- **工程错误**：程序、依赖、数据或 checkpoint 失败；
- **环境错误**：权限、沙箱、配额、资源生命周期和服务中断；
- **过程不确定性**：证据不足，无法可靠归因。

这几种失败需要不同的评价方法，不能简单把最终未完成都算成 Agent 推理能力不足。

## 已有实践

研究者正在构建一个私有的长时程 GPU Research Agent 原型，包含：

- Campaign 级授权与资源预算；
- 持久化科研状态和任务去重；
- 分离 Agent 沙箱与正常 GPU 执行环境；
- 只读资源探测、任务调度和 checkpoint/恢复路径。

**已验证事实（截至 2026-10-17）：** ResourceProbe 真实端到端请求成功完成；相关 Campaign 自主流程通过回归测试；已有 GPU smoke / 恢复实践。

**未完成：** 尚未形成对外可共享的完整 AutoResearch 数据集，也未完成正在准备的四卡 micro32 Campaign 或公开 Benchmark。不能将研究计划作为已有实验结果。

## 拟研究的三个问题

**RQ1 — 过程失败归因。** 如何基于结构化轨迹，将科学、工程、环境及不可判定失败区分开，并量化标注一致性？

**RQ2 — 预算约束下的自治程度。** 在固定 GPU-hours、运行窗口和工具权限下，如何评价 Agent 独立完成有效科研步骤的能力？

**RQ3 — 执行环境对 Eval 的影响。** 当 Sandbox、GPU 资源、存储配额和容器生命周期变化时，Agent 分数有多大变化？如何避免把系统能力错判为模型能力？

## 方法草案

1. 建立非敏感、可复核的事件轨迹格式，记录任务阶段、工具调用、执行结果、证据来源与环境状态。
2. 用小规模、可复现的科研任务建立过程标签和失败归因协议。
3. 在受控环境中注入权限拒绝、磁盘不足、进程中断、重复提交等故障，评估恢复能力。
4. 同时报告最终任务质量、有效科研进展、人工介入、资源成本与可恢复性。
